# Changelog

## Unreleased

- Step 0 spike: model benchmarked on the dev machine; 9B tier and thinking-off method settled.
- Step 1 skeleton: uv workspace; `achilles_net` allowlisted client with outbound log and lint rule; settings, platform checks, model factory; SQLite with Alembic; passphrase login with rate limit, signed cookie and Origin check; streaming chat over SSE with persisted conversations and token counter; `achilles serve`, `doctor`, `db upgrade`; React dashboard with login and chat; CI on ubuntu and macos.
- Step 2 core: MCP manager over stdio with hidden `execute`/`health`; five curated toolsets; slash-command router plus one-word classification; `remind` tool and `reminders` table; approvals queue (`pending → running → done | failed | unknown`, `rejected`, `expired`) with payload hash check and untrusted-content gating of tier-2 actions; `tool_call`, `tool_result` and `approval_required` SSE events; `/api/approvals`, `/api/privacy`, `/api/reminders`; dashboard nav with Approvals and Privacy pages and inline approval cards; stand-in MCP servers for the test suites.
- Step 2 tools: `achilles-mcp-google` (mail, calendar, contacts over Google REST with tier-1 approvals and `execute`), `achilles-mcp-search` (allowlisted DuckDuckGo client and private-address-safe `fetch_page`, rate gate and cache, `WEB_SEARCH` switch), `achilles-mcp-system` (`now`, `parse_datetime`); `achilles-sim` Gmail/Calendar/People simulator with fictional seed; `achilles-mcp-google-setup` consent flow and `docs/GOOGLE_SETUP.md`; `/api/health` reports each server; real-stack e2e suite (real servers, simulator, live model, browser).
- Step 3 demo: `scripts/seed_demo.py` (fictional consultant mailbox and calendar into the simulator or the connected Google account, idempotent, `--wipe`, `--dry-run`) with `scripts/demo_data.py` and `scripts/demo_sim_seed.json`; simulator `messages` insert and `trash`; `scripts/record_demo.md` storyboard; `docs/CASE_STUDY.md` with measured timings; mail-search hint in the system prompt.
- Step 4 skills: client rules in Settings; cached inbox with rule-based triage into Gmail labels and priority contacts; cached calendar with find-a-slot proposals; morning brief and end-of-day digest stored in `daily_briefs` and optionally emailed to self; follow-up tracker that closes on a reply or creates a tone-matched draft; `/brief`, `/inbox`, `/digest`, `/slot`, `/draft` and `/followup` slash commands; APScheduler jobs for mail (3 min), calendar (10 min), reminders (1 min), follow-up checks (10 min), brief (07:30) and digest (18:00) with misfire grace; Today, Inbox, Calendar and Settings pages.
- Step 5 eval and settings: `achilles-eval` with 10 YAML tasks against the simulator, model-agnostic `--base-url`/`--model`, 3 runs each, pass rate, latency and token report, `make eval-smoke`; model tier in client rules with `GET /api/settings/models` and `POST /api/settings/smoke`; full Privacy page with web-search toggle, usage (`$0.00`), and confirmed local-data wipe; `Retry-After` on login 429s.
- Step 6 install and release: `install.sh` (macOS launchd / Linux systemd, Ollama env, wheels into `~/.achilles/venv`, models, service, doctor, dry-run and local-wheel modes); release workflow for `v*` tags and a CI package job; wheel now ships `models/manifest.json` and the built dashboard; `ACHILLES_HOME` drives `.env`; CLI `backup`, `restart`, `logs`, `update`, `model use`, `setup google`, `privacy`, `forget`; nightly backups with 14-day retention; `CLIENT_ONBOARDING.md` and generated `PRIVACY.md`.
